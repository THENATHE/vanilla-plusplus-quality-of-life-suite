# Code audit and upstream refresh — 2026-11-08

Scope: the suite-authored code (`src/`, `components/*/working`, `combined-compat`, `chalk-compat`, `bannerpoint-compat`, `sensible-stackables/compat`, `backpack-crafting`) reviewed against Minecraft 26.3 and the November 2026 developer releases adopted in [1.5.0+26.3](RELEASE_1_5_0.md). Original upstream JARs were not modified. The paused SSO-port track was not touched.

## Fixed

### Required by the upstream updates

| Area | Finding | Fix |
| --- | --- | --- |
| Every module `fabric.mod.json` | Exact pins on Tool Pouch 1.1.10, MapStitch 1.1.7, Tiered Backpacks 1.0.20, Stackables 3.1.1 and the old coordinator would refuse to load; MapStitch 1.2.1 needs Fabric API ≥ 0.163. | Pins and floors moved to the tested releases (Fabric API ≥ 0.165.2). |
| `toolpouch-atlas-elytra/.../AtlasBridge.java` | `ToolPouchUtil.replaceItemInToolPouch` no longer exists, breaking every pouch-atlas save (ticking, ejection, `/atlas` maintenance). | Save through `findSlotsInToolPouch` + `setItemInToolPouch`, which use the same enabled-slot order as the server's atlas list. |
| `toolpouch-atlas-elytra/.../PouchDurabilityMixin.java` | Targeted the removed `updateElytraInToolPouch` (startup crash). Tool Pouch 1.2.0's `damageElytraInToolPouch` now applies Unbreaking through `hurtAndBreak`, writes the live menu container and skips disabled slots. | Mixin and `PouchDurability` removed; upstream wear is equivalent. |
| `AtlasStackCache.java`, `PouchMending.java`, `PouchSsoMending.java`, `BackpackCraftingSlots.maySort` | Tool Pouch 1.2.0 slot toggles (`toolpouch:disabled_slots`) were ignored: the client showed atlases the server never ticks, XP/SSO mending repaired disabled Elytra, and ClientSort moved items across index-based toggles. | Disabled slots are skipped; the atlas cache keys on the component identity. |
| `mapstitch-mixed-scales/.../WorldMapScaleMixin.java` | MapStitch 1.2.1 builds its buttons in field initializers, so the `init` `Tooltip.create` target no longer exists (client crash on opening the world map). | The scale-help tooltip is set on the shadowed `nextScale` button after `init`. |
| `AtlasCartographyMenuMixin.java` | The suite's HEAD cancel swallowed MapStitch's new atlas+atlas copy/merge and blocked shift-clicking a second atlas. | Only atlas+book (the suite's copy) is handled; atlases are routed by MapStitch. |
| `MinimapDimensionMixin.java` | New CENTERED minimap places neighbouring tiles from item `map_center` values, bypassing the authoritative saved-center fix (UPDATING step 7). | `updateMarkers` uses the synchronized saved map center. |
| `AtlasHudLayoutMixin.java` | Map bounds were only captured in STATIC mode, so Tool Pouch details could overlap a centered minimap. | Bounds recorded at the centered-mode scissor call. |
| `combined-compat/.../MapstitchCompat.java`, `AtlasResources.java` | New `mapstitch:atlas_pin` item and `crafting_special_atlas_pin_bulk_dye` serializer were unmapped: vanilla and non-native Fabric clients would be disconnected. | Polymer overlay (iron nugget fallback, original model/tint in the pack) and server-only serializer. |
| `combined-compat/.../CartographyDataSlotsMixin.java` (new) | MapStitch adds three data slots to the vanilla cartography menu; a vanilla client indexes past its empty data-slot list and disconnects. | Data values for that menu are not sent to clients without native MapStitch. |
| `combined-compat/.../ToolpouchCompat.java` | `toolpouch:disabled_slots` was not registered with Polymer. | Registered with the other pouch components. |
| `combined-compat` shulker binding (`ShulkerContainerMixin`, `ShulkerSlotMixin`, `PouchShulkerBinding`, `BoundShulkerContainer`) | Tool Pouch 1.2.0 passes the absolute pouch slot; the suite still treated it as the n-th shulker. Two identical shulkers could both receive the edited contents (duplication), or the menu closed at once. | Removed: upstream now binds to the exact pouch and slot, validates the owner and saves on change. |
| `combined-compat/.../MendingRepairCountMixin.java` | SSO 2.10.3 copies `repair_count` itself; the suite added a second +1 (and on the client). | Removed. |
| `chalk-compat/.../ChalkDestroyParticlesMixin.java` | Handler signatures matched the port, not official Chalk 3.2.0 (InvalidInjectionException with Polymer). | Selectors pinned to full descriptors for the official three-argument hook. |
| `chalk-compat/.../ChalkBreakEffectsMixin.java` (new) | Official 3.2.0 only overrides the destroyBlock hook, so breaking a mark by hand fell back to the generic break effect. | Player breaking is routed through Chalk's own sound/cloud effect, as on 26.2 and in the earlier port. |
| `combined-compat/.../PolymerStackRemovalMixin.java` (new) | Polymer clears fallback defaults with `set(type, null)`; SSO's broken-state hook unboxes a null DAMAGE value. Toolbox stacks (axe fallbacks) could fail to encode and disconnect Fabric-only/vanilla clients, depending on component iteration order. Seen in the first 1.5.0 connection run; the same code path existed in 1.4.5. | Null sets in Polymer's stack conversion become `remove`, which has the same effect. |
| `backpack-crafting/.../SortedCompat.java` | Sorted 0.1.41+26.3 was rejected by the exact version gate, silently dropping the keep-rule suppression and recovery guard. | 0.1.41+26.3 added after checking every target descriptor; portable-menu support included. |
| `src/.../features/ShulkerPickup.java` | Tiered Backpacks 1.0.21 keeps backpack holders out of shulkers; Drops into Shulker could still insert a chestplate with an attached backpack. | `BackpackUtil.isValidContainerHolder` checked. |
| `src/main/resources/resourcepacks/settings_titles` | Complete English copies were missing 90 new upstream keys. | Refreshed from the exact new JARs, keeping the suite's title overrides. |
| `SuiteCapabilities.MAPSTITCH_CHANNELS` | Did not include the new `mapstitch:sync_pins` channel. | Added. |
| `combined-compat/.../PinContainerSizeMixin.java` (new, 1.5.1) | MapStitch 1.2.1's `PinUtil.removeFromContainer` (used by pin placement and pin sharing when `atlasPins.item` is on) copies a container into a fixed 27-slot list and writes it back, deleting slots 27+ of a larger backpack or pouch, and cannot see pins stored past slot 26. | The copy is sized to the stored contents (never below 27), so shulkers are unchanged and larger containers keep every slot. Applied only to MapStitch 1.2.1 (logged and skipped otherwise); the official JAR is untouched. A 1.5.0 baseline reproduces the loss; see qa-pins. |

### Independent findings

| Area | Finding | Fix |
| --- | --- | --- |
| `pets/PetFeatures.java` (`call`) | Happy ghasts and some mounts are unowned, so anyone could bind a horn and teleport the ghast together with other players riding it. | Calling is refused while a player who is neither the caller nor on the caller's team rides the pet. | `mapstitch-mixed-scales` `AtlasMapExtraction`, `AtlasDeathRetention`, `AtlasMapCleanup` | `Inventory.add` deletes whatever does not fit for creative players, losing extracted maps, returned blanks or retained atlases. | `InventoryInsertion.insert` keeps the remainder for the existing drop/retain paths. |
| `MixedScaleMaps.coveringMap` | Created an ItemStack for every same-scale entry before the coverage check, several times per atlas per tick. | Coverage checked first. |
| `shared-region-maps/.../MapstitchMaps.repairAtlas` | Created a stack for every map in every atlas each tick. | Entries whose stored center already matches the saved map are skipped. |
| QA runners | Several client runners defaulted to `DISPLAY=:1` (the desktop). | They now require `SUITE_QA_DISPLAY`. |

## QA fixture updates

Fixtures that encoded upstream details were updated, not the product: MapStitch 1.2's nine-button world-map sidebar, its own marker-label drawing (HUD edge-name scenes now verify whichever overlap case occurs), Stackables 3.1.2's lenient contained-item validation (nested-map allocation case), Sorted 0.1.41's voxelsprout search icon and optional YACL, the new pet-call team rule, and the Fabric API 0.165.2 client game-test module.

The user chose to accept and document it; no mixin. |

The user chose to keep it (2026-11-08): the renamed Experience Bottle and SSO's Mending description stay always on. |
