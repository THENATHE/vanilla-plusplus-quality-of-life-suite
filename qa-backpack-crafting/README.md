# Backpack crafting addon checks

These development-only fixtures run against an exact supplied suite JAR. They are not bundled in the suite.

`run.py <candidate.jar> --work <new-directory>` compiles and executes server-menu checks with and without Polymer. It covers both toolbox tiers and their crafting recipes, ordinary and shift crafting, recipe autofill across backpack/player inventories, ingredient conservation, cake bucket remainders, close cleanup, loss of the required toolbox, protected portable inventories, capacity overflow preservation, full-inventory refusal, and collector pause/resume around an open menu. `--clientsort` adds real ClientSort schema/handler checks, including occupied crafting-grid and result-slot protection. Results record exact artifact hashes.

`network.py --jar <candidate.jar> --label <unique-label> --profiles suite [--without-polymer] [--backpack] [--brbr <exact.jar>] [--cycles 2]` opens the backpack through the developer's original platform method on a connected native client. It operates the recipe-book opener, search and recipe-button mouse callbacks, then sends an output shift-click packet. The server checks conservation after every craft. Cases cover leather and netherite storage capacities with both crafting tiers, viewport and recipe-tab bounds, filtering a 3×3-only recipe from the 2×2 book, and ghost ingredients for an unavailable 3×3 recipe. `--backpack` puts all source planks in the backpack.

Optional BRBR loads the exact supplied file, records its hash, and exercises actual right-click instant crafting. With `--cycles 2`, the second set also exercises Shift-right-click maximum crafting. The default BRBR observer records why pending requests end without changing crafting behavior. The opt-in `--delay-grid` regression mode deliberately reports an unmatched grid for three client ticks after receipt of a result acknowledgment, then delegates to the real matching predicate. This is synthetic incomplete-predicate testing, not delayed network packets; ordinary runs remain the evidence for real transfers. Each run freezes the executed fixture sources before compilation.

The network fixture uses Minecraft screen callbacks, not physical mouse automation. It does not independently establish vanilla-client connection safety, every intermediate backpack size, all BRBR controls, undiscovered recipe placement, or Hotkey Wheel compatibility. The suite's separate connection and wheel checks cover those integration boundaries. Runtime evidence is stored under `evidence/`; fixture sources alone do not imply a passing result.
