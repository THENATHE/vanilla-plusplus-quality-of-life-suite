# combined-compat suite variant

This suite variant keeps the module code and IDs from the developer-target combined shim. It replaces the independent handshake with `SuiteCapabilities`, removes UUID override storage/commands/recovery tasks, and schedules the shared negotiation exactly once before Fabric registry synchronization. Polymer mixins activate only when the corresponding Polymer modules are installed. Without Polymer the original modules initialize normally; the shared configuration protocol still runs. Server mixins are also available in integrated-server processes, but this path requires manual runtime testing. Native Tool Pouch/MapStitch detection for clients running the original mods remains available via existing payload channels. SSO/backpacks use exact suite capability fingerprints. No SSO port target was built or modified.

`ORIGIN.json` records the source baseline and its per-file checksums. The original local projects are preserved unchanged. Root build configuration sets component dependencies and versions. Main/client entrypoints initialize codecs idempotently; the suite client entrypoint calls `SuiteCapabilities.initializeClient()`.

`dependencies.lock.json` now records the actual suite root pinned inputs using component-relative `../../libs/` paths. `upstream-dependencies.lock.json` preserves the previously copied standalone compatibility input list; `ORIGIN.json` preserves the pristine source baseline file hashes.
